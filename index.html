[0] What it does

Look after the Postgres you already have, without leaving the browser

Overview

The last hour of your database, at a glance

Transactions, connections, rows read and written, cache hits, temp files and waiting locks, sampled every ten seconds and charted from the moment you open it. Below them: what is running now, the slowest statements from pg_stat_statements, and every table's dead rows, scans and vacuums.

Advisors

What is worth fixing, and the SQL that fixes it

Unused and duplicate indexes, foreign keys without one, dead rows waiting for a vacuum, sequences running out, sessions idle in a transaction: read from Postgres's own catalogs and statistics, each with why it matters and its fix as SQL. Open the fix in the editor to read it first; nothing runs on its own.

Tables

Every table, every row

Pick a table and read it a thousand rows at a time, with search, filters and each column's type. Add a row, edit a column, or select rows and delete them, in the same view.

SQL

A real editor, and the plan behind the query

Write SQL with highlighting and completion from your schema, keep queries in tabs, and find them again in the history. Results come back as a table, a chart or JSON.

EXPLAIN ANALYZE

Explain anything, change nothing

EXPLAIN ANALYZE runs the statement for its timings, inside a transaction that is rolled back. Explaining a DELETE deletes nothing.

Errors

The crashes your app reports, kept in your database

Your vapor app's backend writes its users' crashes into your own Postgres with reverb-errors, and ryven reads them: grouped, with their stack traces, the request, and the events that led up to them. Resolve, ignore or delete; a resolved crash that comes back shows as regressed.

On a phone

Check on it from anywhere

Every page fits a phone: the charts stack, a tapped error opens on its own, and the editor's queries, history and schemas are a tap away. Behind Google sign-in, it is safe to reach from outside.

[1] Safe by default

It runs whatever SQL it is sent, so it is built around its gate

Loopback only, unless you sign in

Without sign-in ryven listens on this machine alone, and answers only its own page: no other site you visit can reach it, nor a DNS rebinding.

Google sign-in, by allow-list

Set an OAuth client and the addresses allowed in; every request checks the list again.

Read-only, if you like

READ_ONLY=1 makes transactions read-only by default. A role that can only SELECT cannot be talked out of it.

Every statement has a timeout

30 seconds unless you say otherwise, so a runaway query does not hold your database.

TLS to Postgres

sslmode=require or verify-full, as for psql, with Zig's own TLS: still one static binary, no OpenSSL.

Nothing outlives a query

Each one starts clean on its pooled connection: settings, temporary tables and roles never reach the next.

[2] Run it in a minute

Then open http://localhost:8080

Settings beyond the database are environment variables, or a .env beside it: the pool's size, the timeout, read-only, sign-in. The README has them all.

Download it

One binary for Linux (static, x86_64 and arm64) or macOS (Apple silicon and Intel).

# Linux, x86_64

curl -L https://github.com/vic-Rokx/ryven/releases/download/v0.1.1/ryven-v0.1.1-x86_64-linux-musl.tar.gz | tar -xz

./ryven postgres://user:password@localhost:5432/mydb

# macOS, Apple silicon: unquarantine the unsigned binary

curl -L https://github.com/vic-Rokx/ryven/releases/download/v0.1.1/ryven-v0.1.1-aarch64-macos.tar.gz | tar -xz

xattr -d com.apple.quarantine ryven

Or Docker

With a Postgres of its own to look at, published on 127.0.0.1 only.

git clone https://github.com/vic-Rokx/ryven && cd ryven

docker compose up --build

open http://localhost:8080

Or build it

With Zig 0.16, for this machine or any other.

zig build ryven

zig build ryven -Dryven-target=x86_64-linux-musl
